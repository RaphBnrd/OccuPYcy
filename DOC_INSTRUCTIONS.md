# OccuPYcy Documentation Generation Guide (MkDocs)

This document guides you through generating high-quality, browsable documentation and API reference for your Python package using MkDocs and mkdocstrings.

---

## Prerequisites

- Your codebase should have meaningful Python docstrings on modules, classes, and functions.
- You have a `README.md` in your repo.
- Python ≥3.7 is installed in your environment.

---

## Step 1: Install Documentation Tools

```bash
pip install "mkdocstrings[python]"mkdocs mkdocs-material pymdown-extensions 
```

- `mkdocs`: static docs generator (Markdown-powered)
- `mkdocstrings[python]`: automate API docs from your Python docstrings
- `mkdocs-material`: modern, mobile-friendly theme
- `pymdown-extensions`: extra Markdown features (e.g., math support)

---

## Step 2: Prepare Docs Structure

```bash
mkdir docs
```

---

## Step 3: Copy README and Create API Reference

```bash
cp README.md docs/index.md
```

- This makes your README the landing page of your docs site.

### Simplest version of API Reference

Now create a file: `docs/reference.md`  
Paste the following Markdown:

```markdown
# API Reference

::: occupycy

::: occupycy.data

::: occupycy.fit

::: occupycy.likelihood

::: occupycy.models
```

- This will auto-document all classes/functions in `occupycy` and its submodules.

### More detailed API Reference

Alternatively, you can create separate files for each submodule for better organization:

```bash
mkdir docs/api
touch docs/api/data.md docs/api/fit.md docs/api/likelihood.md docs/api/models.md
```

Within each file, add the relevant `::: occupycy.<submodule>` directive. For example, in `docs/api/data.md`:

```markdown
# Data Structures

::: occupycy.data
```

---

## Step 4: Add MkDocs Configuration

Create file: `mkdocs.yml` in repo root with the following content:

```yaml
site_name: OccuPYcy Documentation
repo_url: https://github.com/RaphBnrd/OccuPYcy
nav:
  - Home: index.md
# # If using the simple reference.md file:
#   - API Reference: reference.md
# If using the more detailed reference structure:
  - API Reference:
      - Data: api/data.md
      - Fitting: api/fit.md
      - Models: api/models.md
      - Likelihoods: api/likelihood.md

theme:
  name: material

plugins:
  - search
  - mkdocstrings:
      handlers:
        python:
          paths: [src]
          options:
            docstring_style: auto

markdown_extensions:
  - attr_list
  - pymdownx.arithmatex:
      generic: true

extra_javascript:
  - https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-mml-chtml.js
```

---

## Step 4.5: Paths consistency check

The relative paths may be missing since the `docs/` folder is now the root for MkDocs. If you still want to keep the linked files, add the url of the file in the GitHub repository, by adding `https://github.com/RaphBnrd/OccuPYcy/tree/main/` before the path of the file, or `https://raw.githubusercontent.com/RaphBnrd/OccuPYcy/main/` for images.

Also update the paths of the sections in the table of content since the sections doesn't appear as in GitHub. For instance, `#-features` should be replaced by `#features` in the link of the table of content.

## Step 5: Build and View Locally

```bash
mkdocs serve
```

- Open [http://127.0.0.1:8000/](http://127.0.0.1:8000/) in your browser.
- Check:
  - “Home” page (from README)
  - “API Reference” (autogenerated from code docstrings)

---

## Step 6: Polish and Expand (Optional)

- Add more `.md` files in `docs/` (e.g. tutorials, changelog, benchmarks).  
  Update `nav:` in `mkdocs.yml` to add them.
- Review/clean up your Python docstrings for best effect.
- Add images or figures to `docs/index.md` as needed.

---

## Step 7: Deploy Docs to GitHub Pages

```bash
mkdocs gh-deploy
```

- Your docs will be available at  
  `https://<YOUR-GITHUB-USERNAME>.github.io/<YOUR-REPO-NAME>/`

- To “unpublish” docs later:  
  `mkdocs gh-deploy --clean`

---

## Step 8: Link from Personal Website

- If using [al-folio](https://al-folio.github.io/), edit your nav (e.g., `_data/navigation.yml`):

```yaml
- title: "OccuPYcy Docs"
  url: "https://RaphBnrd.github.io/OccuPYcy/"
```

- Or add as a markdown link where appropriate.

## Notes

- You can always re-run `mkdocs serve` or `mkdocs gh-deploy` after changes.
- Docstrings can be improved any time; you do not need to wait for perfection before publishing.
- For more customization (e.g., logo, custom CSS), see the [mkdocs-material docs](https://squidfunk.github.io/mkdocs-material/).
